# Обслуживание сайта расписания

Практическая шпаргалка: что где менять. Расписания живут в JSON-файлах
`docs/schedules/`, сама страница — `docs/index.html`, иконки — отдельный скрипт.
После любой правки — `git add`, `git commit`, `git push` в `main`,
GitHub Pages сама опубликует.

Сайт: https://golubenkoff.github.io/Liceum_255/

---

## 0. Где что лежит

```
docs/schedules/index.json      ← каталог: список всех расписаний + кто по умолчанию
docs/schedules/class7B.json    ← расписание 7-Б (уроки, звонки, каникулы)
docs/index.html                ← сама страница (данных расписания внутри больше нет)
tools/admin/                   ← локальный редактор расписаний (не публикуется)
```

Страница при запуске читает `schedules/index.json`, показывает список в настройках (⚙),
загружает выбранное расписание и **сохраняет его копию в браузере** — поэтому
установленное приложение открывается мгновенно и работает без интернета.

## 1. Изменить расписание уроков

**Проще всего — через редактор**, см. раздел 5. Он не даст ошибиться в формате
и сам пересоберёт `index.json`.

Руками — открыть `docs/schedules/class7B.json`:

```json
{
  "bells": [
    { "start": "08:30", "end": "09:15" },
    { "start": "09:25", "end": "10:10" }
  ],
  "days": [
    { "dow": 1, "short": "Пон.", "full": "Понеділок",
      "lessons": ["Здоров'я, безпека, добробут", "Фізична культура"] }
  ]
}
```

- `bells[i]` и `lessons[i]` — **одна и та же позиция**: второй урок понедельника идёт
  во второй звонок. Длина `lessons` должна совпадать с длиной `bells`.
- **Пустой урок** (нет пары) — пустая строка `""`.
- `dow` — день недели: 1 = понедельник … 7 = воскресенье. Дней может быть не пять:
  добавь шестой объект с `"dow": 6` — страница сама нарисует лишнюю колонку.
- Время только в формате `"ГГ:ХХ"`. Текст времени в таблице (`08.30–09.15`) страница
  рисует сама из этих значений — дублировать больше ничего не нужно.
- Незнакомый предмет отобразится нормально, просто получит цвет из запасной палитры
  (см. раздел 3).

> ⚠️ Заметки/домашка у пользователей привязаны к **номеру урока и дню**
> (`note_class7B_d1_r0`). Если вставить урок в середину дня — старые заметки
> сдвинутся на соседние предметы. Менять текст предмета безопасно, менять порядок — нет.

## 2. Каникулы и праздники

Поле `holidays` внутри JSON расписания (у каждого класса своё):

```json
"holidays": [
  { "start": "2026-10-26", "end": "2026-11-01", "name": "Осінні канікули" }
]
```

- `start`, `end` — `"РРРР-ММ-ДД"` (с ведущими нулями). Один день — `start` = `end`.
- `name` — что покажется в карточке статуса («Канікули / свято» + этот текст).

Пока сегодняшняя дата попадает в диапазон `[start, end]` — сайт показывает
«Канікули / свято» вместо расписания.

Даты в `class7B.json` на 2026/2027 учебный год — **предварительные,
уточнить по приказу лицея**.

## 3. Цвета предметов в таблице

Функция включается чекбоксом в настройках (⚙), **по умолчанию выключена**.

Работает в два слоя:

1. Базовый список типовых украинских предметов — объект `SUBJECT_COLORS`
   в `docs/index.html` (искать `const SUBJECT_COLORS`). Общий для всех расписаний.
2. Необязательное поле `subjectColors` в JSON расписания — перекрывает базу
   и добавляет свои предметы:

```json
"subjectColors": { "Робототехніка": "#0891b2" }
```

Название должно **точно** (посимвольно) совпадать с текстом урока в `lessons`.
Предметы, которых нет ни там, ни там, получают стабильный цвет по хешу названия
из `FALLBACK_PALETTE`.

В редакторе (раздел 5) это делается пикером цвета, вручную лезть в JSON не нужно.

## 4. Настройки по умолчанию

Объект `DEFAULT_SETTINGS` в `<script>` файла `docs/index.html`:

```js
const DEFAULT_SETTINGS = { theme:'auto', subjectColors:false, progressBar:false, sound:true, scheduleId:null };
```

- `theme`: `'auto'` | `'light'` | `'dark'`
- `subjectColors`: цветная подсветка предметов (сейчас выкл.)
- `progressBar`: прогресс-бар вместо цифрового таймера (сейчас выкл.)
- `sound`: бип+вибро при смене урок↔перемена (сейчас вкл.)
- `scheduleId`: `null` — значит «взять тот, у которого `isDefault: true` в каталоге».
  Как только пользователь выберет расписание в ⚙, сюда запишется его выбор.

Это дефолты **только для новых посетителей** — личный выбор уже открывавших сайт
лежит в `localStorage` и не перезатирается.

Режим «тільки сьогодні / весь тиждень» — отдельная переменная, ищи
`if(!viewMode) viewMode = 'today';`.

Расписание можно навязать ссылкой: `?schedule=class7B` — параметр перекрывает
сохранённый выбор и запоминается. Удобно давать ссылку конкретному классу.

## 5. Редактор расписаний (добавить новый класс)

Локальный инструмент, **не публикуется** на GitHub Pages.

```bash
./tools/admin/serve.sh          # macOS/Linux, порт 8000
./tools/admin/serve.sh 8080     # другой порт
```

```powershell
powershell -ExecutionPolicy Bypass -File tools\admin\serve.ps1
powershell -ExecutionPolicy Bypass -File tools\admin\serve.ps1 -Port 8080
```

Оба скрипта поднимают сервер **из корня репозитория** и сами открывают браузер на
http://localhost:8000/tools/admin/ . Windows-версия работает и без установленного
Python — тогда поднимается встроенный сервер на PowerShell.

Что умеет:

- показывает все расписания из `docs/schedules/`;
- создать новое / **клонировать** существующее (быстрее, чем с нуля) / удалить;
- редактировать сетку уроков, звонки, дни недели, каникулы, цвета;
- переключать ★ «по умолчанию» — снимает флаг у остальных, чтобы их не стало два;
- проверяет формат времени, пересечения звонков, дубли дней, пустые названия.

**Бэкенда нет — редактор не пишет на диск.** Цикл такой:

1. Отредактировал → «⬇ Завантажити `<id>.json`» и «⬇ Завантажити `index.json`».
2. Положил оба файла в `docs/schedules/` (перезаписав старые).
3. Удалённое расписание убрать руками: `git rm docs/schedules/<id>.json`.
4. `git add docs/schedules && git commit && git push`.

Незаконченные правки редактор держит в `localStorage` браузера — можно закрыть
вкладку и вернуться. Кнопка «↻ З диска» перечитывает файлы заново и стирает их.

Новое расписание появится в ⚙ у всех пользователей автоматически (каталог
`index.json` грузится network-first).

## 6. Иконка / логотип PWA (если сменился класс, например 7-Б → 8-А)

**Никогда не редактировать `icon-*.png` вручную.** Только через скрипт из корня репозитория:

```bash
./generate-icons.sh                              # тот же текст "7Б", те же цвета
./generate-icons.sh "8А"                         # новый текст на иконке
./generate-icons.sh "8А" "#2563eb" "#0f172a"     # + свои цвета градиента (верх/низ)
```

Скрипт делает две вещи:
1. Перегенерирует `docs/icon-192.png`, `docs/icon-512.png`, `docs/apple-touch-icon.png`.
2. Автоматически поднимает версию `CACHE_NAME` в `docs/sw.js` — это заставляет уже
   установленные у людей приложения скачать новую иконку при следующем открытии.

Требует ImageMagick (`brew install imagemagick`, если ещё не стоит).

Заголовок страницы (`<h1>`), подзаголовок и дата внизу теперь берутся из полей
`name`, `subtitle`, `updated` JSON-расписания — в `index.html` их править не нужно.
Отдельно поправить стоит только `"name"` / `"short_name"` в `docs/manifest.json`.

## 7. Проверить локально перед пушем

```bash
# страница + расписания (из корня репозитория)
python3 -m http.server 8000
# открыть http://localhost:8000/docs/
```

PWA-функции (service worker, кнопка установки) нормально работают на `localhost`.

Синтаксис JS внутри `index.html`:

```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('docs/index.html','utf8');
new Function(html.match(/<script>([\s\S]*)<\/script>/)[1]);
console.log('JS syntax OK');
"
```

Согласованность каталога и файлов расписаний:

```bash
node -e "
const fs=require('fs');
const cat=JSON.parse(fs.readFileSync('docs/schedules/index.json','utf8'));
const def=cat.schedules.filter(s=>s.isDefault);
if(def.length!==1) throw new Error('isDefault count = '+def.length);
cat.schedules.forEach(s=>{
  const j=JSON.parse(fs.readFileSync('docs/schedules/'+s.file,'utf8'));
  if(j.id!==s.id) throw new Error('id mismatch '+s.file);
  if(!!j.isDefault!==!!s.isDefault) throw new Error('isDefault mismatch '+s.file);
  j.days.forEach(d=>{ if(d.lessons.length>j.bells.length) throw new Error('lessons>bells '+s.id+' dow'+d.dow); });
});
console.log('schedules OK');
"
```

## 8. Автообновление у пользователей

Ничего специально делать не нужно почти никогда: `index.html` и `schedules/*.json`
грузятся network-first без кеша, поэтому у людей с интернетом расписание обновляется
само при следующем открытии / через 5 минут (фоновая проверка), без переустановки.
Локальная копия в `localStorage` перезаписывается, если файл на сервере изменился.

Версию `CACHE_NAME` в `sw.js` нужно поднимать вручную (или через `generate-icons.sh`,
он это уже делает) только когда меняется **состав** списка `ASSETS` — иконки,
`manifest.json`, добавление нового файла расписания в предзагрузку. Правки внутри
уже перечисленных файлов этого не требуют.

Новый файл расписания добавлять в `ASSETS` не обязательно: он закешируется
автоматически, как только пользователь выберет это расписание.
