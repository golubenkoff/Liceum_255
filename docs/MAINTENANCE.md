# Обслуговування сайту розкладу

Практична шпаргалка: що де міняти. Розклади лежать у JSON-файлах `docs/schedules/`,
сама сторінка — `docs/index.html`, іконки — окремий скрипт. Після будь-якої правки —
`git add`, `git commit`, `git push` у `main`, GitHub Pages опублікує сама.

Сайт: https://golubenkoff.github.io/Liceum_255/

---

## 0. Де що лежить

```
docs/schedules/index.json      ← каталог: список усіх розкладів + хто за замовчуванням
docs/schedules/class7B.json    ← розклад 7-Б (уроки, дзвінки, канікули)
docs/index.html                ← сама сторінка (даних розкладу всередині більше немає)
tools/admin/                   ← локальний редактор розкладів (не публікується)
```

Сторінка на старті читає `schedules/index.json`, показує список у налаштуваннях (⚙),
завантажує вибраний розклад і **зберігає його копію в браузері** — тому встановлений
застосунок відкривається миттєво й працює без інтернету.

## 1. Змінити розклад уроків

**Найпростіше — через редактор**, див. розділ 5. Він не дасть помилитись у форматі
й сам перезбере `index.json`.

Руками — відкрити `docs/schedules/class7B.json`:

```json
{
  "bells": [
    { "start": "08:30", "end": "09:15" },
    { "start": "09:25", "end": "10:10" }
  ],
  "days": [
    { "dow": 1, "short": "Пон.", "full": "Понеділок",
      "lessons": ["Здоров'я, безпека, добробут", "Фізична культура"] }
  ]
}
```

- `bells[i]` і `lessons[i]` — **одна й та сама позиція**: другий урок понеділка йде
  у другий дзвінок. Довжина `lessons` має збігатися з довжиною `bells`.
- **Порожній урок** (немає пари) — порожній рядок `""`.
- `dow` — день тижня: 1 = понеділок … 7 = неділя. Днів може бути не п'ять:
  додай шостий об'єкт з `"dow": 6` — сторінка сама намалює зайву колонку.
- Час лише у форматі `"ГГ:ХХ"`. Текст часу в таблиці (`08.30–09.15`) сторінка малює
  сама з цих значень — дублювати більше нічого не треба.
- Новий предмет відобразиться нормально й сам отримає свій колір — палітра генерується
  з назв (див. розділ 3), прописувати його ніде не потрібно.

> ⚠️ Нотатки/домашка користувачів прив'язані до **номера уроку і дня**
> (`note_class7B_d1_r0`). Якщо вставити урок у середину дня — старі нотатки з'їдуть
> на сусідні предмети. Міняти текст предмета безпечно, міняти порядок — ні.

## 2. Канікули та свята

Поле `holidays` всередині JSON розкладу (у кожного класу своє):

```json
"holidays": [
  { "start": "2026-10-26", "end": "2026-11-01", "name": "Осінні канікули" }
]
```

- `start`, `end` — `"РРРР-ММ-ДД"` (з провідними нулями). Один день — `start` = `end`.
- `name` — що покажеться в картці статусу («Канікули / свято» + цей текст).

Поки сьогоднішня дата потрапляє в діапазон `[start, end]` — сайт показує
«Канікули / свято» замість розкладу.

Дати в `class7B.json` на 2026/2027 навчальний рік — **попередні,
уточнити за наказом ліцею**.

## 3. Кольори предметів у таблиці

Функція вмикається чекбоксом у налаштуваннях (⚙), **за замовчуванням вимкнена**.

**Жодних назв предметів у коді немає.** Палітра будується з самого розкладу:
сторінка бере всі предмети з `lessons`, сортує за абеткою й розкидає по колу
відтінків золотим кутом (137.5°) — сусідні кольори виходять максимально різними
за будь-якої кількості предметів. Новому класу налаштовувати нічого не треба.

Готова палітра зберігається в браузері у `schedPalette_v1_<id>` — поруч із копією
розкладу. Це не просто кеш: закріплені кольори **не перетасовуються**, коли в
розкладі з'явиться новий предмет — старі лишаються свої, новий отримує наступний
вільний відтінок.

Перекрити автоматичний колір можна полем `subjectColors` у JSON розкладу:

```json
"subjectColors": { "Робототехніка": "#0891b2" }
```

Пріоритет: `subjectColors` з JSON → збережена автопалітра → щойно згенерований колір.
Назва має **точно** (посимвольно) збігатися з текстом уроку в `lessons`.

У редакторі (розділ 5) для цього є пікер кольору, кнопка **«🎨 Закріпити автопалітру
в JSON»** (записує згенеровані кольори у файл — тоді вони однакові на всіх пристроях)
і **«↺ Скинути всі кольори»** (прибрати з JSON, повернутись до автогенерації).

> У `class7B.json` кольори прописані явно — це підібрана вручну палітра, яка була
> в коді до переходу на JSON. Хочеш автоматичну — «Скинути всі кольори».

## 4. Налаштування за замовчуванням

Об'єкт `DEFAULT_SETTINGS` у `<script>` файла `docs/index.html`:

```js
const DEFAULT_SETTINGS = { theme:'auto', subjectColors:false, progressBar:false, sound:true, scheduleId:null };
```

- `theme`: `'auto'` | `'light'` | `'dark'`
- `subjectColors`: кольорове підсвічування предметів (зараз вимк.)
- `progressBar`: прогрес-бар замість цифрового таймера (зараз вимк.)
- `sound`: біп+вібро при зміні урок↔перерва (зараз увімк.)
- `scheduleId`: `null` — означає «взяти той, у якого `isDefault: true` в каталозі».
  Щойно користувач вибере розклад у ⚙, сюди запишеться його вибір.

Це дефолти **лише для нових відвідувачів** — особистий вибір тих, хто вже відкривав
сайт, лежить у `localStorage` і не перетирається.

Режим «тільки сьогодні / весь тиждень» — окрема змінна, шукай
`if(!viewMode) viewMode = 'today';`.

Розклад можна нав'язати посиланням: `?schedule=class7B` — параметр перекриває
збережений вибір і запам'ятовується. Зручно давати посилання конкретному класу.

## 5. Редактор розкладів (додати новий клас)

Локальний інструмент, **не публікується** на GitHub Pages.

```bash
./tools/admin/serve.sh          # macOS/Linux, порт 8000
./tools/admin/serve.sh 8080     # інший порт
```

```powershell
powershell -ExecutionPolicy Bypass -File tools\admin\serve.ps1
powershell -ExecutionPolicy Bypass -File tools\admin\serve.ps1 -Port 8080
```

Обидва скрипти піднімають сервер **з кореня репозиторію** і самі відкривають браузер на
http://localhost:8000/tools/admin/ . Windows-версія працює і без встановленого
Python — тоді піднімається вбудований сервер на PowerShell.

Що вміє:

- показує всі розклади з `docs/schedules/`;
- створити новий / **клонувати** наявний (швидше, ніж з нуля) / видалити;
- редагувати сітку уроків, дзвінки, дні тижня, канікули, кольори;
- перемикати ★ «за замовчуванням» — знімає прапорець з решти, щоб їх не стало два;
- перевіряє формат часу, перетини дзвінків, дублі днів, порожні назви.

**Бекенду немає — редактор не пише на диск.** Цикл такий:

1. Відредагував → «⬇ Завантажити `<id>.json`» і «⬇ Завантажити `index.json`».
2. Поклав обидва файли в `docs/schedules/` (перезаписавши старі).
3. Видалений розклад прибрати руками: `git rm docs/schedules/<id>.json`.
4. `git add docs/schedules && git commit && git push`.

Незакінчені правки редактор тримає в `localStorage` браузера — можна закрити вкладку
й повернутись. Кнопка «↻ З диска» перечитує файли заново і стирає їх.

Новий розклад з'явиться в ⚙ у всіх користувачів автоматично (каталог `index.json`
вантажиться network-first).

## 6. Іконка / логотип PWA (якщо змінився клас, наприклад 7-Б → 8-А)

**Ніколи не редагувати `icon-*.png` вручну.** Тільки через скрипт із кореня репозиторію:

```bash
./generate-icons.sh                              # той самий текст "7Б", ті самі кольори
./generate-icons.sh "8А"                         # новий текст на іконці
./generate-icons.sh "8А" "#2563eb" "#0f172a"     # + свої кольори градієнта (верх/низ)
```

Скрипт робить дві речі:
1. Перегенеровує `docs/icon-192.png`, `docs/icon-512.png`, `docs/apple-touch-icon.png`.
2. Автоматично піднімає версію `CACHE_NAME` у `docs/sw.js` — це змушує вже встановлені
   в людей застосунки завантажити нову іконку при наступному відкритті.

Потребує ImageMagick (`brew install imagemagick`, якщо ще не стоїть).

Заголовок сторінки (`<h1>`), підзаголовок і дата внизу тепер беруться з полів
`name`, `subtitle`, `updated` JSON-розкладу — в `index.html` їх правити не треба.
Окремо варто поправити лише `"name"` / `"short_name"` у `docs/manifest.json`.

## 7. Перевірити локально перед пушем

```bash
# сторінка + розклади (з кореня репозиторію)
python3 -m http.server 8000
# відкрити http://localhost:8000/docs/
```

PWA-функції (service worker, кнопка встановлення) нормально працюють на `localhost`.

Синтаксис JS усередині `index.html`:

```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('docs/index.html','utf8');
new Function(html.match(/<script>([\s\S]*)<\/script>/)[1]);
console.log('JS syntax OK');
"
```

Узгодженість каталогу й файлів розкладів:

```bash
node -e "
const fs=require('fs');
const cat=JSON.parse(fs.readFileSync('docs/schedules/index.json','utf8'));
const def=cat.schedules.filter(s=>s.isDefault);
if(def.length!==1) throw new Error('isDefault count = '+def.length);
cat.schedules.forEach(s=>{
  const j=JSON.parse(fs.readFileSync('docs/schedules/'+s.file,'utf8'));
  if(j.id!==s.id) throw new Error('id mismatch '+s.file);
  if(!!j.isDefault!==!!s.isDefault) throw new Error('isDefault mismatch '+s.file);
  j.days.forEach(d=>{ if(d.lessons.length>j.bells.length) throw new Error('lessons>bells '+s.id+' dow'+d.dow); });
});
console.log('schedules OK');
"
```

## 8. Автооновлення в користувачів

Спеціально робити нічого не треба майже ніколи: `index.html` і `schedules/*.json`
вантажаться network-first без кешу, тому в людей з інтернетом розклад оновлюється
сам при наступному відкритті / через 5 хвилин (фонова перевірка), без перевстановлення.
Локальна копія в `localStorage` перезаписується, якщо файл на сервері змінився.

Версію `CACHE_NAME` у `sw.js` треба піднімати вручну (або через `generate-icons.sh`,
він це вже робить) лише коли змінюється **склад** списку `ASSETS` — іконки,
`manifest.json`, додавання нового файла розкладу в передзавантаження. Правки всередині
вже перелічених файлів цього не потребують.

Новий файл розкладу додавати в `ASSETS` не обов'язково: він закешується автоматично,
щойно користувач вибере цей розклад.
