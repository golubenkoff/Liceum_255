# Обслуживание сайта расписания 7-Б

Практическая шпаргалка: что где менять. Все правки — в файле `docs/index.html`,
кроме иконок (отдельный скрипт). После любой правки — `git add`, `git commit`,
`git push` в `main`, GitHub Pages сама опубликует.

Сайт: https://golubenkoff.github.io/Liceum_255/

## 1. Изменить расписание уроков

Таблица — обычный HTML, начинается около [`index.html:530`](index.html#L530).

Каждая строка урока выглядит так:

```html
<tr data-start="08:30" data-end="09:15">
  <td>1</td>
  <td class="time">08.30–09.15</td>
  <td>Здоров'я, безпека, добробут</td>   <!-- Понеділок -->
  <td>Фізика</td>                        <!-- Вівторок -->
  <td>Географія</td>                     <!-- Середа -->
  <td>Українська література</td>         <!-- Четвер -->
  <td>Географія</td>                     <!-- П'ятниця -->
</tr>
```

Порядок колонок жёстко фиксированный: №, Час, Пн, Вт, Ср, Чт, Пт.

- **Поменять предмет** — просто изменить текст внутри нужной `<td>`. Ничего больше
  трогать не нужно, подсветка "текущий/следующий" считается по `data-start`/`data-end`,
  а не по названию предмета.
- **Пустой урок** (нет пары) — `<td class="empty">—</td>`.
- **Поменять время звонков** — поменять `data-start`/`data-end` у `<tr>` **и** текст
  в соседней `<td class="time">…</td>` (они не связаны, дублируются вручную — не забудь
  оба места).
- **Добавить/убрать урок (строку)** — скопировать/удалить весь `<tr data-start=…>…</tr>`
  целиком. Ничего в JS менять не надо, скрипт сам находит все строки с `data-start`.
- Если в школе поменяется предмет, которого раньше не было в списке — он всё равно
  отобразится нормально, просто получит случайный цвет из запасной палитры (см. раздел 3)
  вместо продуманного — это не ошибка, а особенность.

## 2. Каникулы и праздники

Массив `HOLIDAYS` в начале `<script>`, см. [`index.html:650`](index.html#L650). Сейчас там
лежат предварительные даты на 2026/2027 учебный год (уточнить позже по приказу лицея):

```js
const HOLIDAYS = [
  { start:'2026-10-26', end:'2026-11-01', name:'Осінні канікули' },
  { start:'2026-12-24', end:'2027-01-10', name:'Зимові канікули' },
  { start:'2027-03-22', end:'2027-03-28', name:'Весняні канікули' },
  { start:'2027-07-01', end:'2027-08-31', name:'Літні канікули' },
];
```

Добавляй/меняй строки. Формат:

- `start`, `end` — `'РРРР-ММ-ДД'` (год-месяц-день, с ведущими нулями). Один день —
  `start` и `end` совпадают.
- `name` — что покажется в карточке статуса ("Канікули / свято" + этот текст).

Пока сегодняшняя дата попадает в диапазон `[start, end]` — сайт показывает
"Канікули / свято" вместо расписания, дальше проверять не нужно ничего.

## 3. Цвета предметов в таблице

Функция включена по чекбоксу в настройках (⚙), **по умолчанию выключена**.

Соответствие предмет → цвет — объект `SUBJECT_COLORS`, [`index.html:666`](index.html#L666):

```js
const SUBJECT_COLORS = {
  "Здоров'я, безпека, добробут": '#0891b2',
  'Фізика': '#7c3aed',
  ...
};
```

- Чтобы поменять цвет предмета — поменять hex-значение.
- Чтобы задать цвет новому предмету — добавить строку `'Назва предмету': '#hex',`.
  Название должно **точно** совпадать (посимвольно) с текстом в ячейке таблицы.
- Предметы, которых нет в этом списке, получают цвет автоматически (хеш названия →
  цвет из `FALLBACK_PALETTE` рядом) — стабильно одинаковый для одного и того же названия,
  но некрасиво продуманный. Лучше явно прописать.

## 4. Настройки по умолчанию

Объект `DEFAULT_SETTINGS` в `<script>` (искать `const DEFAULT_SETTINGS`):

```js
const DEFAULT_SETTINGS = { theme:'auto', subjectColors:false, progressBar:false, sound:true };
```

- `theme`: `'auto'` | `'light'` | `'dark'`
- `subjectColors`: `true`/`false` — цветная подсветка предметов (сейчас выкл.)
- `progressBar`: `true`/`false` — прогресс-бар вместо цифрового таймера (сейчас выкл.)
- `sound`: `true`/`false` — бип+вибро при смене урок↔перемена (сейчас вкл.)

Это дефолты **только для новых посетителей** — у кого уже открыт сайт, его личный
выбор в настройках лежит в `localStorage` браузера и не перезатирается этими значениями.

Режим "тільки сьогодні / весь тиждень" — отдельная переменная, ищи
`if(!viewMode) viewMode = 'today';` — сейчас по умолчанию "тільки сьогодні".

## 5. Иконка / логотип PWA (если сменился класс, например 7-Б → 8-А)

**Никогда не редактировать `icon-*.png` вручную.** Только через скрипт из корня репозитория:

```bash
./generate-icons.sh                              # тот же текст "7Б", те же цвета
./generate-icons.sh "8А"                         # новый текст на иконке
./generate-icons.sh "8А" "#2563eb" "#0f172a"     # + свои цвета градиента (верх/низ)
```

Скрипт делает две вещи:
1. Перегенерирует `docs/icon-192.png`, `docs/icon-512.png`, `docs/apple-touch-icon.png`.
2. Автоматически поднимает версию `CACHE_NAME` в `docs/sw.js` — это заставляет уже
   установленные у людей приложения скачать новую иконку при следующем открытии.

Требует ImageMagick (`brew install imagemagick`, если ещё не стоит).

Если поменялось название класса не только на иконке, но и в тексте — не забудь также
поправить:
- `<h1>7-Б клас</h1>` и `<p class="sub">…</p>` в `docs/index.html`
- `"name"` / `"short_name"` в `docs/manifest.json`
- `<title>` в `<head>` `docs/index.html`

## 6. Проверить локально перед пушем

```bash
cd docs
python3 -m http.server 8000
# открыть http://localhost:8000/index.html
```

PWA-функции (service worker, кнопка установки) нормально работают на `localhost`.

Быстрая проверка, что не сломан синтаксис JS внутри `index.html`:

```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('docs/index.html','utf8');
new Function(html.match(/<script>([\s\S]*)<\/script>/)[1]);
console.log('JS syntax OK');
"
```

## 7. Автообновление у пользователей

Ничего специально делать не нужно почти никогда: сайт грузит `index.html`
network-first без кеша, поэтому у людей с интернетом расписание/тексты обновляются
сами при следующем открытии/через 5 минут (фоновая проверка), без переустановки.

Версию `CACHE_NAME` в `sw.js` нужно поднимать вручную (или через `generate-icons.sh`,
он это уже делает) только когда меняются файлы, которые кешируются один раз при
установке service worker — то есть иконки и `manifest.json`. Правки текста/расписания
внутри `index.html` этого не требуют.
