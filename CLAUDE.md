# CLAUDE.md

Контекст для Claude Code при работе с этим репозиторием.

## Что это

Одностраничный сайт расписания 7-Б класса (Ліцей № 255, класний керівник Лапач М.П.).
Опубликован через GitHub Pages из папки `docs/` ветки `main`:
**https://golubenkoff.github.io/Liceum_255/**

Никакого билд-шага нет — чистый HTML/CSS/JS, вся страница в одном файле `docs/index.html`
(inline `<style>` + inline `<script>`). Это осознанно: страницу редактирует один человек
руками, фреймворк/сборка была бы лишней.

**Данные расписаний вынесены из HTML** в `docs/schedules/*.json` — так один и тот же
`index.html` обслуживает несколько классов/учителей, и никому не надо лезть в код.

## Структура репозитория

```
docs/                     ← публикуется GitHub Pages (Settings → Pages → main /docs)
  index.html              ← вся страница: разметка + CSS + JS в одном файле (без данных расписания)
  schedules/
    index.json            ← каталог расписаний: id, name, file, isDefault
    class7B.json          ← расписание 7-Б: bells, days, holidays, (опц.) subjectColors
  manifest.json           ← PWA-манифест (иконка, имя, цвета)
  sw.js                   ← service worker: офлайн-кеш + автообновление
  icon-192.png            ← иконка PWA 192×192
  icon-512.png            ← иконка PWA 512×512
  apple-touch-icon.png    ← иконка 180×180 для iOS "На экран Домой"
  MAINTENANCE.md          ← пошаговые инструкции: как поменять расписание/каникулы/иконку
tools/admin/              ← локальный редактор расписаний, НЕ публикуется Pages
  index.html, admin.css, admin.js
  serve.py                ← статика + write-API (PUT/DELETE на docs/schedules/*.json)
  serve.sh / serve.ps1    ← поднимают сервер из корня репо и открывают редактор
generate-icons.sh         ← скрипт в корне репо: перегенерирует иконки + бампит кеш sw.js
```

## Формат JSON расписания

```json
{
  "id": "class7B",              // = имя файла без .json
  "name": "7-Б клас",           // идёт в <h1> и <title>
  "subtitle": "Ліцей № 255 · Класний керівник: Лапач М.П.",
  "isDefault": true,            // ровно один такой на весь каталог
  "updated": "2026-08-30",      // показывается в футере
  "bells":   [{ "start": "08:30", "end": "09:15" }],
  "days":    [{ "dow": 1, "short": "Пон.", "full": "Понеділок", "lessons": ["Фізика"] }],
  "holidays":[{ "start": "2026-10-26", "end": "2026-11-01", "name": "Осінні канікули" }],
  "subjectColors": { "Робототехніка": "#0891b2" }   // опц., перекрывает автопалитру
}
```

`lessons[i]` соответствует `bells[i]`; пустой слот — `""`. `dow` = 1..7 (пн..вс),
количество дней не фиксировано. `holidays` и `subjectColors` необязательны.
`isDefault` дублируется в каталоге и в самом файле — админка держит их в синхроне.

## Как это устроено (внутри index.html)

- **Загрузка расписания** — `bootSchedule()`: id берётся из `?schedule=<id>` → сохранённого
  `settings.scheduleId` → `isDefault` в каталоге → `FALLBACK_ID` (`class7B`). Сначала
  мгновенный рендер из копии в `localStorage` (`schedCache_v1_<id>`), параллельно —
  сетевое обновление каталога и самого JSON, и перерисовка, если файл изменился.
  Ни копии, ни сети — карточка ошибки с кнопкой "спробувати ще раз".
- **Таблица расписания** — `<table id="schedule">` в разметке пустая, её строит
  `renderScheduleTable()` из JSON: каждая строка урока получает `data-start="HH:MM"
  data-end="HH:MM"`, `<td class="time">` рисуется из тех же значений. JS каждую секунду
  (`setInterval(update, 1000)`) сравнивает текущее время с атрибутами и подсвечивает
  текущий/следующий урок — то есть **DOM таблицы остаётся источником истины для `update()`**,
  JSON только его наполняет.
- **Дни недели не захардкожены**: `dayCols` (dow → индекс колонки `<tr>`) и `DAY_NAMES`
  строятся в `renderScheduleTable()`. `update()` работает с `dow` (1..7, вс = 7), а не с
  `getDay()`. "Выходной" = в расписании нет дня с таким dow; "следующий учебный день"
  считает `nextSchoolDayLabel()`, а не «всегда понедельник».
- **Палитра предметов** — названий предметов в коде нет. `buildPalette()` берёт предметы
  из расписания, сортирует и раскидывает по кругу оттенков золотым углом (137.5°),
  результат кладёт в `localStorage.schedPalette_v1_<id>`. Хранилище нужно не ради
  скорости, а ради стабильности: новый предмет получает следующий свободный оттенок,
  уже назначенные цвета не перетасовываются. Приоритет в `activeColors`:
  `schedule.subjectColors` (ручной выбор из админки) → сохранённая автопалитра.
  Тот же генератор продублирован в `tools/admin/admin.js` (чистая функция, правки —
  в обоих местах).
- **Статус-карточка** сверху — "Зараз йде урок: …" / "Перерва. Наступний урок: …" /
  "Сьогодні вихідний" / "Канікули".
- **Каникулы/праздники** — `let HOLIDAYS`, наполняется из `schedule.holidays`. Если
  сегодняшняя дата попадает в диапазон — показывается "Канікули/свято" вместо расписания.
  В `class7B.json` сейчас предварительные даты на 2026/2027 учебный год, требуют уточнения
  по приказу лицея (см. `docs/MAINTENANCE.md`).
- **Настройки** (шестерёнка ⚙ вверху страницы, хранятся в `localStorage.rozkladSettings`):
  - `scheduleId` — выбранное расписание. `null` = взять `isDefault` из каталога.
  - `theme` — авто/светлая/тёмная. По умолчанию `auto`.
  - `subjectColors` — цветные полоски/подложка по предмету. **По умолчанию выключено.**
    (это флажок «показывать», не путать с полем `subjectColors` в JSON расписания)
  - `progressBar` — прогресс-бар урока/перемены вместо цифрового таймера. По умолчанию выключено.
  - `sound` — короткий бип + вибро при смене урок↔перемена. **По умолчанию включено.**
    Учти: браузеры блокируют звук без жеста пользователя (autoplay policy) — первый бип
    после открытия страницы может быть беззвучным, пока юзер не кликнет хоть куда-то.
- **Вид "тільки сьогодні"** — кнопка над таблицей переключает полную неделю / только
  сегодняшний день списком. По умолчанию `today` (задаётся один раз, дальше запоминается
  в `localStorage.viewMode`).
- **Нотатки/домашка** — клик по предмету в таблице открывает `prompt()`, текст лежит в
  `localStorage` по ключу `note_{scheduleId}_d{dow}_r{номер_урока}`. Точка-индикатор на
  ячейке = есть заметка. Ключ позиционный, поэтому перестановка уроков в JSON сдвинет
  чужие заметки — менять текст предмета безопасно, порядок нет.
  `migrateLegacyNotes()` одноразово переносит старые ключи `note_d1_r0` в `class7B`
  (флаг `notesMigrated_v2`) — не удалять, пока живы установленные приложения.
- **PWA / установка на телефон**:
  - `manifest.json` + `sw.js` + иконки — стандартный набор для "Добавить на экран Домой".
  - Блок "📲 Встановити як застосунок" внизу страницы: кнопка (если браузер поддерживает
    `beforeinstallprompt`, т.е. Android/desktop Chrome) + разворачиваемые инструкции для
    Android и отдельно для iOS Safari (там нативного диалога нет — только текстовая инструкция).
  - Если сайт уже открыт как установленное приложение (`display-mode: standalone`) —
    блок сам скрывается и показывает "✅ Застосунок уже встановлено".
- **Автообновление PWA** — `sw.js` тянет `index.html` **и `schedules/*.json`** network-first
  с `cache:'no-store'` (т.е. при наличии интернета всегда свежий контент, без правок версии
  кеша); в обеих ветках fetch-хендлера успешный ответ пишется в кеш, поэтому новый файл
  расписания становится офлайновым сам, как только его один раз открыли. Страница раз в
  5 минут и при возврате на вкладку дёргает `registration.update()`; когда новый service
  worker становится активным — страница сама делает `location.reload()`.
- Версию `CACHE_NAME` в `sw.js` вручную поднимать нужно, только когда меняется **состав**
  списка `ASSETS` (иконки, `manifest.json`, добавление файла в предзагрузку) — при правке
  уже перечисленных файлов не нужно. `generate-icons.sh` делает это автоматически.
  Учти: `cache.addAll` атомарный — если хоть один путь из `ASSETS` даёт 404, установка SW
  падает целиком и офлайн ломается у всех.

## Как работать с проектом

**Локальный просмотр** (из корня репо, чтобы работали и страница, и админка):
```bash
./tools/admin/serve.sh 8000     # статика + write-API для редактора
# страница:  http://localhost:8000/docs/
# редактор:  http://localhost:8000/tools/admin/

python3 -m http.server 8000     # только статика (редактор без записи)
```
Service worker и install-prompt нормально работают на `localhost` (Chrome считает его
доверенным origin), так что PWA-функциональность можно тестировать локально.

**Редактор расписаний:** `./tools/admin/serve.sh` (macOS/Linux) или
`powershell -ExecutionPolicy Bypass -File tools\admin\serve.ps1` (Windows — работает
и без установленного Python, тогда поднимает свой TcpListener-сервер). Оба сами
открывают браузер.

У редактора **два режима**, он определяет их сам запросом `GET /__admin/ping`:

- **режим записи** — поднят через эти скрипты, сервер отдаёт write-API, и каждая правка
  через `FLUSH_DELAY` (700 мс тишины) уходит `PUT`'ом прямо в `docs/schedules/<id>.json`
  плюс пересобранный `index.json`. Остаётся только закоммитить. Расписание с ошибками
  валидации на диск не пишется — намеренно, чтобы в репозиторий не уехал битый файл.
- **режим загрузки** — открыт через обычный `python3 -m http.server` или `file://`.
  Писать некуда: правки живут в `localStorage`, файлы качаются кнопками и кладутся руками.

Кнопки скачивания работают в обоих режимах. Ограничения write-API (loopback-only,
только `docs/schedules/`, только `[A-Za-z0-9_-]+.json`, валидный JSON ≤512 КБ) —
в шапке `serve.py`; в `serve.ps1` продублирована та же логика для Windows без Python.

**Формат записи:** `prettyJSON()` в `admin.js` — короткие объекты в одну строку,
массивы уроков всегда построчно. Это не косметика: файлы остаются пригодными для
правки руками, а диффы — маленькими. Сервер пишет тело запроса дословно (только
проверяет, что это валидный JSON), поэтому формат задаёт редактор, а не сервер.

**Деплой:** просто `git push` в `main` — GitHub Pages сама пересоберёт `docs/`.
Изменения в `index.html` подхватываются у уже установленных пользователей автоматически
(см. автообновление выше), обычно в течение нескольких минут/при следующем открытии.

**Обновить расписание / каникулы / иконку** — подробные пошаговые инструкции в
[`docs/MAINTENANCE.md`](docs/MAINTENANCE.md). Начинай оттуда, не с этого файла.

**Иконки:** никогда не редактируй `icon-*.png` вручную — перегенерируй скриптом:
```bash
./generate-icons.sh              # тот же класс "7Б", те же цвета
./generate-icons.sh "8А"         # сменился класс — новый текст на иконке
```
Скрипт сам кладёт PNG в `docs/` и бампит `CACHE_NAME` в `sw.js`.

## Проверка после правок

Файл большой и монолитный (HTML+CSS+JS вместе), поэтому после любой правки стоит
как минимум:
```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('docs/index.html','utf8');
new Function(html.match(/<script>([\s\S]*)<\/script>/)[1]);
console.log('JS syntax OK');
"
```
— это ловит синтаксические опечатки в `<script>` до пуша.

Плюс проверка согласованности каталога и файлов расписаний (полный скрипт —
в `docs/MAINTENANCE.md`, раздел 7): ровно один `isDefault`, `id` файла совпадает
с `id` в каталоге, `lessons` не длиннее `bells`.

Headless Chrome на этом проекте **зависает** (страница держит `setInterval`, и
`--virtual-time-budget` не истекает) — не трать на него время. Логику рендера
надёжнее проверять в Node: вытащить нужную функцию из `<script>` регуляркой,
подсунуть заглушку `document.getElementById` и сравнить сгенерированный HTML
с эталоном.

## Договорённости по стилю

- Весь текст на странице (для учеников/родителей) — **украинский**.
  `docs/MAINTENANCE.md` — тоже украинский: её читает тот, кто ведёт расписание,
  а не разработчик. Этот файл (`CLAUDE.md`) и комментарии в коде — русский,
  так исторически сложилось в этом репо.
- Не тащить сюда фреймворки/бандлеры без явного запроса — страница должна открываться
  как один статический файл. Требование "всё в одном файле" относится к `docs/index.html`;
  `tools/admin/` — отдельный инструмент, там html/css/js разнесены осознанно.
- Не возвращать данные расписания обратно в `index.html` — если нужен ещё один класс,
  это новый JSON в `docs/schedules/` плюс строка в каталоге, а не правка разметки.
- Цветовая база: зелёный (#16a34a/#22c55e) = "сейчас идёт", жёлтый (#f59e0b/#d97706) =
  "дальше/перемена". Новые статусы старайся вписывать в эту же логику, а не изобретать
  третий несвязанный цвет.
