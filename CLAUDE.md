# CLAUDE.md

Контекст для Claude Code при роботі з цим репозиторієм.

## Що це

Односторінковий сайт розкладу 7-Б класу (Ліцей № 255, класний керівник Лапач М.П.).
Опублікований через GitHub Pages з теки `docs/` гілки `main`:
**https://golubenkoff.github.io/Liceum_255/**

Жодного білд-кроку немає — чистий HTML/CSS/JS, уся сторінка в одному файлі `docs/index.html`
(inline `<style>` + inline `<script>`). Це свідомо: сторінку редагує одна людина
руками, фреймворк/збірка була б зайвою.

**Дані розкладів винесені з HTML** у `docs/schedules/*.json` — так один і той самий
`index.html` обслуговує кілька класів/учителів, і нікому не треба лізти в код.

## Структура репозиторію

```
docs/                     ← публікується GitHub Pages (Settings → Pages → main /docs)
  index.html              ← уся сторінка: розмітка + CSS + JS в одному файлі (без даних розкладу)
  schedules/
    index.json            ← каталог розкладів: id, name, file, isDefault
    class7B.json          ← розклад 7-Б: bells, days, holidays, (опц.) subjectRooms/subjectColors
  manifest.json           ← PWA-маніфест (іконка, назва, кольори)
  sw.js                   ← service worker: офлайн-кеш + автооновлення
  icon-192.png            ← іконка PWA 192×192
  icon-512.png            ← іконка PWA 512×512
  apple-touch-icon.png    ← іконка 180×180 для iOS "На екран Домівка"
  MAINTENANCE.md          ← покрокові інструкції: як змінити розклад/канікули/іконку
tools/admin/              ← локальний редактор розкладів, НЕ публікується Pages
  index.html, admin.css, admin.js
  serve.py                ← статика + write-API (PUT/DELETE на docs/schedules/*.json)
  serve.sh / serve.ps1    ← піднімають сервер з кореня репо і відкривають редактор
generate-icons.sh         ← скрипт у корені репо: перегенеровує іконки + бампить кеш sw.js
```

## Формат JSON розкладу

```json
{
  "id": "class7B",              // = ім'я файла без .json
  "name": "7-Б клас",           // іде в <h1> і <title>
  "subtitle": "Ліцей № 255 · Класний керівник: Лапач М.П.",
  "isDefault": true,            // рівно один такий на весь каталог
  "updated": "2026-08-30",      // показується у футері
  "bells":   [{ "start": "08:30", "end": "09:15" }],
  "days":    [{ "dow": 1, "short": "Пон.", "full": "Понеділок", "lessons": ["Фізика"] }],
  "holidays":[{ "start": "2026-10-26", "end": "2026-11-01", "name": "Осінні канікули" }],
  "subjectRooms":  { "Фізика": "214" },             // опц., номер кабінету
  "subjectColors": { "Робототехніка": "#0891b2" }   // опц., перекриває автопалітру
}
```

`lessons[i]` відповідає `bells[i]`; порожній слот — `""`. `dow` = 1..7 (пн..нд),
кількість днів не фіксована. `holidays`, `subjectRooms` і `subjectColors` необов'язкові.
`isDefault` дублюється в каталозі й у самому файлі — адмінка тримає їх у синхроні.

## Як це влаштовано (всередині index.html)

- **Завантаження розкладу** — `bootSchedule()`: id береться з `?schedule=<id>` → збереженого
  `settings.scheduleId` → `isDefault` у каталозі → `FALLBACK_ID` (`class7B`). Спершу
  миттєвий рендер із копії в `localStorage` (`schedCache_v1_<id>`), паралельно —
  мережеве оновлення каталогу й самого JSON, і перемальовування, якщо файл змінився.
  Ні копії, ні мережі — картка помилки з кнопкою "спробувати ще раз".
- **`dropMissingSelection()`** — після оновлення каталогу перевіряє, що збережений вибір
  там ще є. Якщо розклад видалили/перейменували, його копія і палітра прибираються з
  `localStorage`, `settings.scheduleId` скидається, вантажиться дефолтний. Без цього
  сторінка вічно показувала б "привида" з локальної копії: мережеве оновлення для нього
  дає 404, а гілка «`currentSchedule` вже є» відпрацьовує раніше й нічого не міняє.
  Саме так виглядає слід від видаленого тестового розкладу.
- Провал фонового оновлення **не мовчазний**: у `#scheduleHint` з'являється попередження,
  що показано збережену копію. Інакше людина дивиться на старі дані й не має як це помітити.
- **Таблиця розкладу** — `<table id="schedule">` у розмітці порожня, її будує
  `renderScheduleTable()` з JSON: кожен рядок уроку отримує `data-start="HH:MM"
  data-end="HH:MM"`, `<td class="time">` малюється з тих самих значень. JS щосекунди
  (`setInterval(update, 1000)`) порівнює поточний час з атрибутами і підсвічує
  поточний/наступний урок — тобто **DOM таблиці лишається джерелом істини для `update()`**,
  JSON лише його наповнює.
- **Дні тижня не захардкоджені**: `dayCols` (dow → індекс колонки `<tr>`) і `DAY_NAMES`
  будуються в `renderScheduleTable()`. `update()` працює з `dow` (1..7, нд = 7), а не з
  `getDay()`. "Вихідний" = у розкладі немає дня з таким dow; "наступний навчальний день"
  рахує `nextSchoolDayLabel()`, а не «завжди понеділок».
- **Палітра предметів** — назв предметів у коді немає. `buildPalette()` бере предмети
  з розкладу, сортує і розкидає по колу відтінків золотим кутом (137.5°),
  результат кладе в `localStorage.schedPalette_v1_<id>`. Сховище потрібне не заради
  швидкості, а заради стабільності: новий предмет отримує наступний вільний відтінок,
  уже призначені кольори не перетасовуються. Пріоритет в `activeColors`:
  `schedule.subjectColors` (ручний вибір з адмінки) → збережена автопалітра.
  Той самий генератор продубльований у `tools/admin/admin.js` (чиста функція, правки —
  в обох місцях).
- **Кабінети** — `schedule.subjectRooms` (предмет → номер) кладеться в `activeRooms`,
  `roomFor()` віддає номер або порожній рядок. У таблиці — `<span class="room">` під
  назвою предмета, у вигляді "тільки сьогодні" — чип праворуч. Прив'язка до предмета,
  не до конкретного уроку.
- **Назва предмета читається з `data-subject`, а не з `textContent`** — у комірці тепер
  ще й номер кабінету, тому `textContent` дав би "Фізика214". Єдина точка доступу —
  `subjectOf(cell)`; порожній слот має `data-subject=""`, тож перевірка стала
  `if(!subject)` замість колишнього порівняння з сентинелом `'—'`.
- **Статус-картка** зверху — "Зараз йде урок: …" / "Перерва. Наступний урок: …" /
  "Сьогодні вихідний" / "Канікули".
- **Канікули/свята** — `let HOLIDAYS`, наповнюється з `schedule.holidays`. Якщо
  сьогоднішня дата потрапляє в діапазон — показується "Канікули/свято" замість розкладу.
  У `class7B.json` зараз попередні дати на 2026/2027 навчальний рік, потребують уточнення
  за наказом ліцею (див. `docs/MAINTENANCE.md`).
- **Налаштування** (шестерня ⚙ вгорі сторінки, зберігаються в `localStorage.rozkladSettings`):
  - `scheduleId` — вибраний розклад. `null` = взяти `isDefault` з каталогу.
  - `theme` — авто/світла/темна. **За замовчуванням `dark`.**
  - `palette` — оформлення: `classic` (типове) / `blue` / `violet` / `rose` / `flag`.
    Атрибут `data-palette` на `<html>`, як і тема. Вибір — випадним списком.
  - `subjectColors` — кольорові смужки/підкладка за предметом. **За замовчуванням вимкнено.**
    (це прапорець «показувати», не плутати з полем `subjectColors` у JSON розкладу)
  - `progressBar` — прогрес-бар уроку/перерви замість цифрового таймера. За замовчуванням вимкнено.
  - `sound` — короткий біп + вібро при зміні урок↔перерва. **За замовчуванням увімкнено.**
    Врахуй: браузери блокують звук без жесту користувача (autoplay policy) — перший біп
    після відкриття сторінки може бути беззвучним, доки юзер кудись не клікне.
  - `silenceMinute` — хвилина мовчання о 9:00. **За замовчуванням увімкнено.**
  - `alerts` / `alertRegion` / `alertInterval` — інтеграція з сервісом повітряних тривог.
    За замовчуванням вимкнено; регіон `'м. київ'`, інтервал 30 с.
- **Хвилина мовчання** — `isSilenceMinute()` + константи `SILENCE_START`/`SILENCE_LEN`.
  Щодня 09:00:00–09:01:00, **включно з вихідними й канікулами**. У таблицю уроків
  навмисно не додається: це не урок, а восьмий рядок таблиці зсунув би нумерацію
  і поламав позиційні ключі нотаток. Назва уроку не зникає — стає дрібнішою рядком
  нижче. Біп на цьому переході не звучить.
- **Повітряні тривоги** — [NEPTUN](https://neptun.in.ua/developers),
  `GET https://neptun.in.ua/api/v1/alerts`, без ключів, `Access-Control-Allow-Origin: *`,
  тому статична сторінка ходить туди напряму.
  - **Ubilling API сюди не годиться** — він не віддає жодного CORS-заголовка, браузер
    не дає прочитати відповідь. Перевірено на всіх їхніх ендпоінтах; JSONP теж немає.
    Без власного серверного проксі варіант неробочий — не витрачай на нього час знову.
  - Умови NEPTUN, зашиті в UI і **обов'язкові**: §3 — видиме посилання на джерело
    (`#alertsCredit` + футер модалки з картою); §5 — прямо казати, що це не офіційна
    система оповіщення, і відсилати до `@air_alert_ua`; §4 — не частіше ніж раз на 5 с
    (наш мінімум 10 с, дефолт 30 с, у прихованій вкладці опитування зупиняється).
  - `ALERT_REGIONS` — 27 регіонів зашито константою (окремого ендпоінта немає,
    `oblasts.geojson` важить ~161 КБ). Ключі з малої літери; `'м. київ'` і `'київська'` —
    **різні** регіони. Регіон під тривогою, якщо він є в `oblasts` АБО якщо хоч один
    запис у `raions` має `oblast` з його назвою.
  - Частота запитів обмежена в трьох місцях: `alertsInFlight` (один запит за раз),
    `ALERTS_MIN_GAP_MS` = 5 с усередині `startAlerts()` (щоб жоден виклик не міг
    частити — це умова §4) і перевірка давності в обробнику `visibilitychange`
    (перемикання застосунків на телефоні не має означати запит на кожен дотик).
  - «Сервіс не відповідає» показується лише коли `alertsFailures > 0`. Сама лише
    давність даних цього не означає: у фоні ми навмисно припиняємо опитування.
  - Модуль ізольований: будь-яка помилка мережі/парсингу гаситься всередині, стан
    лишається "тривоги немає", розклад працює як завжди. Стан тривоги **не кешується**
    в `localStorage` (на відміну від розкладу): він застаріває за секунди, і показати
    збережене "тривога" після відбою гірше, ніж не показати нічого.
  - `update()` щосекунди робить `card.className = 'status-card'`, тому тривога й хвилина
    мовчання накладаються **всередині тіку**, у спільному хвості функції. Гілки
    канікул/вихідного через це більше не роблять ранній `return` — не повертай їх.
- **Вигляд "тільки сьогодні"** — кнопка над таблицею перемикає повний тиждень / лише
  сьогоднішній день списком. За замовчуванням `today` (задається один раз, далі
  запам'ятовується в `localStorage.viewMode`).
- **Нотатки/домашка** — клік по предмету в таблиці відкриває `prompt()`, текст лежить у
  `localStorage` за ключем `note_{scheduleId}_d{dow}_r{номер_уроку}`. Крапка-індикатор на
  комірці = є нотатка. Ключ позиційний, тому перестановка уроків у JSON зсуне
  чужі нотатки — міняти текст предмета безпечно, порядок ні.
  `migrateLegacyNotes()` одноразово переносить старі ключі `note_d1_r0` у `class7B`
  (прапорець `notesMigrated_v2`) — не видаляти, доки живі встановлені застосунки.
- **PWA / встановлення на телефон**:
  - `manifest.json` + `sw.js` + іконки — стандартний набір для "Додати на екран Домівка".
  - Блок "📲 Встановити як застосунок" внизу сторінки: кнопка (якщо браузер підтримує
    `beforeinstallprompt`, тобто Android/desktop Chrome) + інструкції, що розгортаються, для
    Android і окремо для iOS Safari (там нативного діалогу немає — лише текстова інструкція).
  - Якщо сайт уже відкрито як встановлений застосунок (`display-mode: standalone`) —
    блок сам ховається і показує "✅ Застосунок уже встановлено".
- **Жодних зовнішніх ресурсів, крім API тривог.** Шрифтових файлів у репозиторії
  немає: текст малюється системним стеком (`system-ui, -apple-system, 'Segoe UI',
  Roboto…`), цифри таймера — моноширинним (`ui-monospace, SF Mono, Consolas…`, щоб
  таймер не «стрибав»). Ніяких Google Fonts і CDN: зовнішній хост ламає офлайн
  (service worker чужі origin'и навмисно не кешує) і суперечить вимозі «все лежить
  у теці проєкту». Якщо колись додаєш файл — клади поруч і дописуй у `ASSETS` у `sw.js`.
  Space Grotesk і Inter були й прибрані свідомо: у першого **немає кирилиці** (на
  українському тексті він і не працював), а другий не вартий 67 КБ завантаження там,
  де система вже дає добрий шрифт.
- **Перезавантаження після оновлення SW** має два запобіжники, і обидва потрібні:
  `hadController` (при першому візиті контролера ще немає, `clients.claim()` теж
  дає `controllerchange` — перезавантажувати щойно відкриту сторінку нема сенсу) і
  лічильник `sessionStorage.swReloads` (максимум 2 на вкладку), щоб збій SW не
  перетворився на нескінченний цикл «reload → новий контролер → reload».
- **Список "тільки сьогодні" перемальовується лише коли змінився HTML**
  (`lastTodayHTML` + `paintTodayView()`). `update()` крутиться щосекунди, а список
  міняється кілька разів на день — без цієї перевірки сторінка перебудовувала б його
  86 400 разів на добу. Скидай `lastTodayHTML = null` там, де міняється розклад.
- **Автооновлення PWA** — `sw.js` тягне `index.html` **і `schedules/*.json`** network-first
  з `cache:'no-store'` (тобто за наявності інтернету завжди свіжий контент, без правок версії
  кешу); в обох гілках fetch-хендлера успішна відповідь пишеться в кеш, тому новий файл
  розкладу стає офлайновим сам, щойно його один раз відкрили. Сторінка раз на
  5 хвилин і при поверненні на вкладку смикає `registration.update()`; коли новий service
  worker стає активним — сторінка сама робить `location.reload()`.
  На початку fetch-хендлера стоїть байпас чужих origin'ів (`req.url` не з нашого origin →
  `return`). Він потрібен: без нього запити до API тривог падали б у cache-first гілку,
  і стан тривоги назавжди лишився б таким, яким його побачили вперше — відбою користувач
  не дочекався б. Не прибирати.
- Версію `CACHE_NAME` у `sw.js` вручну піднімати треба лише тоді, коли змінюється **склад**
  списку `ASSETS` (іконки, `manifest.json`, додавання файла в передзавантаження) — при правці
  вже перелічених файлів не треба. `generate-icons.sh` робить це автоматично.
  Врахуй: `cache.addAll` атомарний — якщо хоч один шлях з `ASSETS` дає 404, установка SW
  падає цілком і офлайн ламається у всіх.

## Як працювати з проєктом

**Локальний перегляд** (з кореня репо, щоб працювали і сторінка, і адмінка):
```bash
./tools/admin/serve.sh 8000     # статика + write-API для редактора
# сторінка:  http://localhost:8000/docs/
# редактор:  http://localhost:8000/tools/admin/

python3 -m http.server 8000     # тільки статика (редактор без запису)
```
Service worker і install-prompt нормально працюють на `localhost` (Chrome вважає його
довіреним origin), тож PWA-функціональність можна тестувати локально.

**Редактор розкладів:** `./tools/admin/serve.sh` (macOS/Linux) або
`powershell -ExecutionPolicy Bypass -File tools\admin\serve.ps1` (Windows — працює
і без встановленого Python, тоді піднімає свій TcpListener-сервер). Обидва самі
відкривають браузер.

У редактора **два режими**, він визначає їх сам запитом `GET /__admin/ping`:

- **режим запису** — піднято через ці скрипти, сервер віддає write-API, і кожна правка
  через `FLUSH_DELAY` (700 мс тиші) іде `PUT`'ом прямо в `docs/schedules/<id>.json`
  плюс перезібраний `index.json`. Лишається тільки закомітити. Розклад з помилками
  валідації на диск не пишеться — навмисне, щоб у репозиторій не поїхав побитий файл.
- **режим завантаження** — відкрито через звичайний `python3 -m http.server` або `file://`.
  Писати нікуди: правки живуть у `localStorage`, файли качаються кнопками і кладуться руками.

Кнопки завантаження працюють в обох режимах. Обмеження write-API (loopback-only,
лише `docs/schedules/`, лише `[A-Za-z0-9_-]+.json`, валідний JSON ≤512 КБ) —
в шапці `serve.py`; у `serve.ps1` продубльована та сама логіка для Windows без Python.

**Формат запису:** `prettyJSON()` в `admin.js` — короткі об'єкти в один рядок,
масиви уроків завжди построчно. Це не косметика: файли лишаються придатними для
правки руками, а діфи — маленькими. Сервер пише тіло запиту дослівно (лише
перевіряє, що це валідний JSON), тому формат задає редактор, а не сервер.

**Деплой:** просто `git push` у `main` — GitHub Pages сама перезбере `docs/`.
Зміни в `index.html` підхоплюються у вже встановлених користувачів автоматично
(див. автооновлення вище), зазвичай протягом кількох хвилин / при наступному відкритті.

**Оновити розклад / канікули / іконку** — детальні покрокові інструкції в
[`docs/MAINTENANCE.md`](docs/MAINTENANCE.md). Починай звідти, не з цього файла.

**Іконки:** ніколи не редагуй `icon-*.png` вручну — перегенеруй скриптом:
```bash
./generate-icons.sh              # той самий клас "7Б", ті самі кольори
./generate-icons.sh "8А"         # змінився клас — новий текст на іконці
```
Скрипт сам кладе PNG у `docs/` і бампить `CACHE_NAME` у `sw.js`.

## Перевірка після правок

Файл великий і монолітний (HTML+CSS+JS разом), тому після будь-якої правки варто
щонайменше:
```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('docs/index.html','utf8');
new Function(html.match(/<script>([\s\S]*)<\/script>/)[1]);
console.log('JS syntax OK');
"
```
— це ловить синтаксичні одруківки в `<script>` до пушу.

Плюс перевірка узгодженості каталогу й файлів розкладів (повний скрипт —
у `docs/MAINTENANCE.md`, розділ 8): рівно один `isDefault`, `id` файла збігається
з `id` у каталозі, `lessons` не довші за `bells`.

Headless Chrome на цьому проєкті **зависає** (сторінка тримає `setInterval`, і
`--virtual-time-budget` не спливає) — не витрачай на нього час. Логіку рендеру
надійніше перевіряти в Node: витягнути потрібну функцію з `<script>` регуляркою,
підсунути заглушку `document.getElementById` і порівняти згенерований HTML
з еталоном.

## Домовленості щодо стилю

- **Усе українською**: текст на сторінці (для учнів/батьків), `docs/MAINTENANCE.md`,
  коментарі в коді, цей файл. Ідентифікатори, ключі JSON і назви файлів — латиницею,
  як зараз.
- Не тягнути сюди фреймворки/бандлери без явного запиту — сторінка має відкриватись
  як один статичний файл. Вимога "все в одному файлі" стосується `docs/index.html`;
  `tools/admin/` — окремий інструмент, там html/css/js рознесені свідомо.
- Не повертати дані розкладу назад у `index.html` — якщо потрібен ще один клас,
  це новий JSON у `docs/schedules/` плюс рядок у каталозі, а не правка розмітки.
- **Палітри** (`data-palette` на `<html>`) задають ЛИШЕ кольорові змінні:
  `--body-grad-1..3`, `--accent`, `--accent-2`, `--glow-1/2`, `--head-bg`,
  `--today-bg` і заливки картки `--card-lesson/break/idle/holiday`. Нейтральне
  (текст, картки, межі) лишається за темою. Кожну палітру треба описати **двічі** —
  для темної і для світлої теми: поверх темного тла потрібні глибокі відтінки,
  поверх світлого бліді, інакше фон вигорає або текст втрачає контраст. Блоки
  палітр стоять НИЖЧЕ блоків тем, інакше тема перетирала б палітру.
- **`classic`** — кольори першої версії (гілка `Universal-2`). Її особливість:
  **уся плашка таймера виразно міняє колір під стан** — світло-зелена під урок,
  бурштинова під перерву. Картка тут світла в ОБИДВОХ темах (як було: світла
  картка на темному тлі), тому текст на ній завжди темний — окремим блоком
  `html[data-palette="classic"] .status-card…`. Якщо натомість підмішувати колір
  у темне тло картки, виходить темно-зелене на темному й напис стану тоне
  (перевірено заміром). Заливки тут **суцільні, без альфи**: з прозорістю темне
  тло просвічувало і глушило колір — жовтий ставав брудно-бежевим (заміряно
  (243,234,196) замість (253,231,144)). Решта палітр лишає скляний відтінок.
- У палітрі `flag` фон сам читається як прапор (синє вгорі → тепле золото внизу)
  плюс золота риска під `h1` і під шапкою таблиці через `--flag-rule`. Підкладка
  «сьогодні» там навмисно СИНЯ, а не золота: жовтий у таблиці вже означає
  «наступний урок», і золотий заголовок дня зливався б із цим значенням.
- **Перелив на фоні** — `body::before` і `body::after`, `position:fixed`,
  `z-index:-1` (малюються над власним фоном body, але під усім вмістом).
  Анімуються лише `transform` і `opacity` — композит на GPU. `filter:blur`
  тут не застосовувати: на такій площі він відчутно гальмує телефон, а
  м'якість і так дає радіальний градієнт.
- **Друк** — окремий блок `@media print`: альбомна A4, чорне на білому, лишаються
  тільки заголовок і таблиця. Кольорові заливки на папері шкідливі: на ч/б принтері
  зелена й жовта підкладки стають однаково сірими, тож стан передається **формою** —
  суцільна рамка + «← зараз», пунктирна + «← далі». Кнопка «Друк» видима лише у
  вигляді тижня (у «тільки сьогодні» друкувати нічого).
- **`--st-lesson` / `--st-break` / `--st-break-label` / `--st-holiday`** —
  кольори станів у статус-картці, теж залежні від теми. Світлі м'ятний і
  бурштиновий гарно світяться на темній картці, але на світлій зникають
  (заміряно 1.2:1 — таймер практично невидимий). Не став тут константу.
- **`--hl-text`** — колір тексту в підсвічених клітинках таблиці (зелена «зараз»,
  жовта «далі»). Заливка там **напівпрозора**, тому поверх темної теми виходить
  темне тло і потрібен білий текст, а поверх світлої — світле тло і потрібен темний.
  Жорсткий `color:#fff` чи `#241a0a` тут завжди ламає одну з тем: заміряно, у
  протилежній контраст падає до ~1.3:1, тобто напис зникає. Міняєш ці клітинки —
  бери `var(--hl-text)`, не константу.
- Кольорова база: зелений (#16a34a/#22c55e) = "зараз іде", жовтий (#f59e0b/#d97706) =
  "далі/перерва". Нові статуси намагайся вписувати в цю ж логіку, а не вигадувати
  третій незв'язаний колір.
